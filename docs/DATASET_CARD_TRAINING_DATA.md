# wayfinder-training-data

Status: DRAFT, not published. This card describes a gated dataset that has not been uploaded. The repository `hweller1/wayfinder-training-data` does not exist yet.

**Built with Muse Spark Open.**

These are the 1,383 code-search trajectories used to fine-tune [wayfinder-qwen](https://huggingface.co/hweller1/wayfinder-qwen-35b-a3b) (and, with a different tokenizer render, wayfinder-glimmer). Each example is one task: a short request (the subject line of a real commit), the agent's reasoning, its calls to `grep`, `glob`, `read_file`, `semantic_search` and `report`, the tool results, and a final ranked list of `path:start-end` ranges. Access is by request and manual approval.

## Size and contents

| Item | Count |
|---|---|
| Examples | 1,383 |
| Tasks | 344 |
| Repositories | 153 (of the 244 in the training split; 242 of those 244 are permissively licensed) |
| Muse Spark Open trajectories | 1,350 (1,347 from self-hosted replicas of the open weights, 3 from a third-party host of the same open weights; none from Meta's API) |
| Agents-A1-35B trajectories | 33 |
| Tokens | 47.2M with the Qwen3.6 chat template (6.9M assistant tokens, all of which carried loss); 41.6M with the Muse Glimmer render |
| Examples that offered `semantic_search` | 1,062 (754 called it at least once) |

The numbers come from the build summaries of the training data (`teacher_v3_summary.json`, `qwen_v3_summary.json`) and the model card. The on-disk size is filled in at upload time.

## Schema

One JSON object per line.

| Field | Type | Meaning |
|---|---|---|
| `id` | string | `<task_id>\|teacher\|s<seed>` or the Agents-A1 id |
| `tools_variant` | string | `scout5` (five tools, with `semantic_search`) or `scout4_grep_only` |
| `messages` | list | Chat messages: one `system`, one `user` (the request), then `assistant` turns with `reasoning` and `tool_calls` and `tool` results, ending with a `report` call. Tool-call arguments are objects |
| `meta.source` | string | `teacher` (Muse Spark Open) or `a1` (Agents-A1-35B) |
| `meta.task_id`, `meta.repo`, `meta.seed` | string | The task, the `owner/name` repository and the rollout seed |
| `meta.category` | string | Task category (see below) |
| `meta.semantic`, `meta.semantic_calls` | bool, int | Whether `semantic_search` was offered, and how many times it was called |
| `meta.turns`, `meta.n_gold`, `meta.recall`, `meta.all_gold_found` | number | Turns used, number of right files, recall and the all-gold flag from the filter |
| `meta.tokens`, `meta.assistant_tokens` | int | Example length under the Qwen3.6 template |

The tool schemas and system prompt are the ones in the GitHub repository (`serve/scout_tool_specs.json`, `serve/scout_product_prompt.md`). Fields removed before release (token ids, loss spans, serving endpoints) are listed in the release plan. Whether the right-file lists and base commits ship in a separate `tasks.jsonl` is an open decision recorded there.

## Task sources and shapes

Tasks were mined from real commits in public repositories: the commit subject line is the question and the files the commit changed are the answers. The split is by repository, so no repository in this data appears in the development, test or 200-task held-out sets. Seven repositories also appear in an early end-to-end study, whose 17 tasks were excluded from this data. For the 357 training-split tasks used across all versions of this data (the 344 here differ from them by at most 13), the mix is:

| Category | Tasks | Language | Tasks | Right files per task | Tasks |
|---|---|---|---|---|---|
| implementing_new_features | 138 | Python | 83 | 1 | 62 |
| refactoring | 74 | TypeScript/JavaScript | 72 | 2 to 3 | 132 |
| paying_tech_debt | 54 | Rust | 71 | 4 to 6 | 116 |
| modernize | 36 | C/C++ | 41 | 7 or more | 47 |
| cybersecurity_bug_finding | 29 | Go | 38 | | |
| onboarding | 19 | Ruby, Other, Swift, C#, Java/Kotlin | 15, 14, 9, 8, 6 | | |
| db_schema_rot, qa_over_codebases | 4, 3 | | | | |

The median is 3 right files per task (range 1 to 12), and the request is one line of a median 8 words. Right files include test files. Swift, C# and Java/Kotlin are thin. See the model card for what the model does well on these shapes and where it does not.

## How it was built

Muse Spark Open 816B-A42B searched each task with Scout's own explore loop (up to 40 turns, temperature 0.85, top_p 0.95, earlier reasoning kept between turns, the line "Report as soon as the evidence covers the brief; do not exhaust the turn budget." in the system prompt). 5,683 teacher rows went through a filter that kept only runs that found every gold file, opened every file they reported and called `report` in time, within the task's 75th-percentile turn count and 49,152 tokens, and de-duplicated on task and seed. That left 1,350. Thirty-three strict all-gold trajectories from Agents-A1-35B were added. Training was LoRA supervised fine-tuning, documented in the model card.

Because of this filter the data is not a sample of what a search agent does. It contains only successful runs, and it favours tasks where the teacher succeeded.

## Limitations

- One teacher, one filter, one task source. Every example is a run that succeeded, so the data has no recovery from failure beyond what happens inside a successful run.
- Task wording is English and is a commit subject line, which is shorter and terser than a user's question. Tasks come from public repositories, and up to 13 tasks come from one repository, so the tasks are not independent samples of the world's repositories.
- Language coverage is uneven (see the table above). Swift, C# and Java/Kotlin are thin.
- Assistant turns include the teacher's reasoning text, which may contain errors, and tool results contain code excerpts that may contain contributor names, emails or stale secrets from public history. The pre-release scans are listed in the release plan, and no scan finds everything.
- One repository in the wider training set is AGPL-3.0 and one could not be license-checked (see the release plan for what was done about them).
- The per-example counts in this card come from build summaries. The 344 task ids were not saved outside the training volume, so the category, language and file-count tables are for the 357-task union.
